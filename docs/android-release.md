# Releasing Healthy on Android

Healthy ships to Android through EAS Build and Google Play. Releases run from
the EAS Workflow [`android-release.yml`](../.eas/workflows/android-release.yml);
profiles live in [`eas.json`](../eas.json). The version code is kept by EAS
(`appVersionSource: remote`, `autoIncrement` on `production`), so there is no
`android.versionCode` in `app.json`.

## One-time setup

### 1. Expo project

```bash
pnpm dlx eas-cli login
pnpm dlx eas-cli init
```

`init` writes `extra.eas.projectId` and `owner` into `app.json`. Commit them.

### 2. Google Play Console

1. Register at [Google Play Console](https://play.google.com/apps/publish/signup/) ($25, one time).
2. **Create app**: name `Healthy`, English (United States), App, Free.
3. Complete the **Dashboard** tasks:
   - **Privacy policy**: a public URL. You need to provide one.
   - **App access**: all functionality is available without special access.
   - **Ads**: none.
   - **Content rating**: questionnaire (health utility, all ages).
   - **Target audience**: 18+.
   - **Health apps declaration**: health management and records, not a diagnostic device.
   - **Data safety**: records are stored only on the device. When Google Drive
     sync is connected, they are end-to-end encrypted and written to the user's
     own Drive `appDataFolder`. Nothing is collected by or shared with the developer.
4. Personal developer accounts created after November 2023 must run a closed
   test (12 testers, 14 days) before production access. Internal testing, used
   here, is exempt.

### 3. Service account for `eas submit`

1. Play Console → **Users and permissions** / **API access**: link a Google Cloud project and create a service account named `eas-submit` (Cloud Console, no extra roles needed).
2. Create a JSON key for it. Keep the file **outside the repository**.
3. In Play Console, invite the service account and grant it the app `Healthy` with permission to create and manage releases on testing tracks.
4. Upload the key to EAS:

```bash
pnpm dlx eas-cli credentials --platform android
```

Choose `production` → Google Service Account Key → upload the JSON.

### 4. Google sign-in for Drive sync

Android signs in through Google Play services, which identifies the app by
package name and signing certificate. In Google Cloud Console →
**APIs & Services → Credentials**, using the same project as the Web client in
`EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, create an **OAuth client ID of type Android**
for package `com.deividas.healthy` once per SHA-1:

| Build                                 | Where to get the SHA-1                                                                                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local debug / emulator                | `keytool -list -v -keystore android/app/debug.keystore -alias androiddebugkey -storepass android` (the React Native template key generated by prebuild) |
| EAS builds (`preview`, `development`) | `pnpm dlx eas-cli credentials --platform android` → the keystore's SHA1 fingerprint                                                                     |
| Play Store installs                   | Play Console → **Test and release → App integrity → App signing** → app signing key certificate SHA-1                                                   |

Also enable the **Google Drive API** and keep `drive.appdata` on the OAuth
consent screen. Until the consent screen is verified, add your Google account
as a test user.

### 5. Link GitHub to the Expo project

On expo.dev → **healthy → Project settings → GitHub**, install the Expo GitHub
app and connect `DeividasK/healthy`. EAS Workflows then run on pushes to the
repository; no GitHub secret is needed.

## Releasing

Android ships with every release; see [Releasing Healthy](releasing.md).

- **Every push to `release`** builds a `production` AAB on EAS and submits it
  to the Play **Internal testing** track. Pushes to `main` publish nothing.
- **Manual:** expo.dev → **healthy → Workflows → Run workflow** on the
  `release` branch, or
  `pnpm dlx eas-cli workflow:run .eas/workflows/android-release.yml`.
- **An installable APK, no store involved:**
  `pnpm dlx eas-cli build --platform android --profile preview`.

Follow builds and submissions under **Workflows** on expo.dev.

`eas.json` submits with `releaseStatus: draft`, so each release needs **Start
rollout** in Play Console, with its release notes pasted from the GitHub
Release. The first release stays a draft until the store listing and
declarations above are complete.

## Installing on your phone

1. Play Console → **Test and release → Testing → Internal testing → Testers**.
2. Create an email list containing the Google account signed in on your phone.
3. Copy the **Join on Android** link, open it on the phone, tap **Accept invite**, then **Download it on Google Play**.
4. Install **Healthy** from the Play Store. Later builds arrive as normal updates.

## Local Android development

```bash
pnpm expo run:android          # builds and installs a dev build on a device or emulator
pnpm expo start                # then open the app; Metro serves the JS
```

`android/` is generated (`expo prebuild`) and gitignored. If Gradle reports
"SDK location not found", set `ANDROID_HOME=$HOME/Library/Android/sdk`.
